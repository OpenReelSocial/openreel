# ADR-0002: Foundational technology stack

- **Status:** Accepted
- **Date:** 2026-08-29
- **Deciders:** ZackMurry

## Context

The workspace phase of the development backlog (DEV-006 onward) cannot start
without a backend language, package manager, and toolchain, and DEV-005 exists
specifically to record those decisions rather than let them accumulate as
implicit choices inside scaffolding commits.

Before this ADR, the only accepted decision was ADR-0001 (domain and Lexicon
namespace). The backlog in `docs/dev-environment-tasks.yaml` already assumed
Node, pnpm, and TypeScript, and the committed `.editorconfig`, `.gitignore`, and
`.vscode/` configuration assumed a TypeScript/Python/Swift repository, but no
ADR recorded any of it. The project plan in `docs/reference/project-plan.md`
never names a backend language at all; its single Node.js reference describes
Mastodon's architecture, not OpenReel's.

Three constraints shaped the choices:

1. **AT Protocol's reference implementations are TypeScript.** `@atproto/*`,
   including the PDS, relay, and Lexicon codegen, is published as TypeScript.
   Choosing another backend language would mean either reimplementing protocol
   plumbing or running a polyglot split across the services that touch it most.
2. **The Lexicon toolchain generates TypeScript.** Per ADR-0001 the project
   authors its own `social.openreel.*` record types, so generated bindings are on
   the critical path for the AppView, feed generator, and iOS client contracts.
3. **A capstone team of seven with an iOS focus.** A stack that shares one
   language across every backend service keeps review and handoff cheap.

## Decision

### Backend

| Concern | Choice |
|---|---|
| Language | TypeScript, strict, extending `tsconfig.base.json` |
| Runtime | Node.js 22 LTS, pinned in `.nvmrc` and `engines` |
| Package manager | pnpm 10, pinned via `packageManager` and activated by Corepack |
| Monorepo task runner | Turborepo |
| HTTP framework | Express 5 |
| Test framework | Vitest |
| Formatter | Prettier |
| Linter | ESLint 9 flat config with typescript-eslint, `recommendedTypeChecked` |

### Other components

| Concern | Choice |
|---|---|
| iOS client | Swift / SwiftUI, AVFoundation + HLS, Xcode project generated by XcodeGen |
| Content classifier | Python, formatted and linted by Ruff, tested with pytest |
| Infrastructure as code | AWS CDK v2 in TypeScript |
| Local dependencies | Docker Compose: Postgres 16, Redis 7.4 |
| PDS and relay | Reused upstream `bluesky-social` implementations, operated and configured by OpenReel rather than authored |

`make check` is the canonical pre-PR verification command and runs
`format-check`, `lint`, `typecheck`, and `test`.

## Alternatives considered

| Option | Why not |
|---|---|
| Go or Rust backend | Better raw performance per node, but forfeits the `@atproto/*` reference implementations and TypeScript Lexicon codegen. Neither is a bottleneck at capstone scale, where video delivery is handled by S3/CloudFront rather than application code. |
| Python backend (unifying with the classifier) | The classifier needs the Python ML ecosystem, but the protocol-facing services need the AT Protocol ecosystem. Keeping Python confined to `services/classifier/` isolates the polyglot boundary to one service instead of spreading it across all of them. |
| Biome instead of Prettier + ESLint | Faster and single-binary, and it was already referenced in `.vscode/`. Rejected because ESLint's type-aware rules and the `@atproto`/plugin ecosystem matter more here than formatter speed. This ADR supersedes the Biome assumption in the committed editor config. |
| npm or Yarn instead of pnpm | pnpm's strict `node_modules` layout prevents accidental undeclared dependencies between services, which is the failure mode most likely to bite a seven-person monorepo. |
| Nx instead of Turborepo | Heavier generator/plugin model than this repository needs; Turborepo's task graph plus caching is sufficient. |
| Fastify or Hono instead of Express | Both are faster and more modern. Express was chosen for familiarity and ecosystem depth across the team, and the `createApp()` factory pattern in each service keeps the framework replaceable behind one seam. |
| Jest instead of Vitest | Vitest needs no separate transform configuration for ESM + TypeScript, which is where Jest costs the most setup effort in this layout. |

## Consequences

- One language covers the AppView, feed generator, Lexicon packages, and CDK
  infrastructure, so a contributor moves between them without a context switch.
- Generated Lexicon bindings can be consumed directly by backend services. The
  iOS client still needs a separate Swift generation path.
- Node is single-threaded per process. CPU-bound work — video transcoding,
  classification inference — must not live in these services; it belongs in the
  Python classifier or a dedicated media pipeline.
- Express 5 has a thinner middleware ecosystem than Express 4 and no built-in
  schema validation, so request validation will need an explicit choice later.
- Reusing the upstream PDS and relay means tracking upstream releases, but avoids
  reimplementing the most security-sensitive parts of the protocol.
- Reversal cost is asymmetric. Swapping the HTTP framework or test runner is
  cheap and local. Swapping the language or package manager would invalidate the
  entire workspace phase.

## Unresolved

These are deliberately not decided here, to avoid speculative ADRs:

- **CDN.** `docs/reference/project-plan.md` contains unreconciled Cloudflare and
  CloudFront assumptions; DEV-050 assumes CloudFront. `docs/README.md` names this
  as a known conflict. Decide when work reaches media delivery.
- **Request validation / schema library** for Express 5.
- **Database access layer** — query builder, ORM, or plain driver — and the
  migration tool. Decide with the first real schema.
- **Structured logging library**, pending DEV-020.
- **Whether `services/gateway/` is needed at all.** `AGENTS.md` lists it "where
  applicable" and no backlog task creates it. `services/admin/` exists as an
  internal status dashboard for local testing and is explicitly not a gateway,
  not a public surface, and not authenticated.
- **Whether OpenReel operates its own relay** or consumes an upstream firehose.
- **Swift formatter and linter** (DEV-015) and the Swift Lexicon generation path.
- **Git hook runner.** The reference layout this repository is modelled on uses
  Python `pre-commit`; a TypeScript-first equivalent has not been chosen.

## Revisit if

- A protocol-facing service becomes CPU-bound in a way Node cannot absorb and
  moving the work to a dedicated service is not sufficient.
- The AT Protocol ecosystem's reference implementations stop being TypeScript.
- Team composition shifts such that TypeScript is no longer the common language.
